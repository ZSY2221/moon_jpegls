## 当前实现优先级

1. 先完成补件和公开证据；不要等 M1 代码全部结束才提交复审材料。
2. M1 只扩大合法 NEAR；复用现有 8/12/16 位与默认 MAXVAL，避免同时改变位深、色彩布局和扫描组织。
3. M1 是向完整目标演进的首个可验证步骤，不能代替对完整终点的明确承诺。
4. 进入每个新阶段时，先建立失败样例及独立期望，再修改实现。
5. 前端优先维护当前真实能力和证据入口；不把规划能力显示为可选并运行假结果。

## 分工

Codex：源码与参数审计、标准矩阵、核心与 CLI/SDK 的兼容改动、参考实现驱动和回归、提交与版本记录。

Antigravity：在固定提交上复验新增参数的工作台行为、真实数值显示、错误热图和取消／暂停；视觉改动围绕已支持的能力。核心协议由同一任务负责人协调，避免两工具同时改 Worker/codec 状态机。

## 复审公开入口要求

README 中英版分别链接当前范围、最终计划与路线；表单写实际可访问的提交链接。所有统计标注是历史、当前公开版还是当前本地候选。开发承诺、实现状态、执行结果使用不同措辞。
